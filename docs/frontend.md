# Frontend conventions

Applies to `apps/web`: Next.js App Router, React, TypeScript, and Tailwind CSS. Follow the shared [code quality rules](code-quality.md) and [design system](design-system.md).

- Organize routes and layouts in `src/app`. Keep feature components and hooks near their consumers; move components into a shared folder when multiple features need them.
- Use PascalCase for React components, `useX` for hooks, and kebab-case for ordinary files. Preserve Next.js special filenames such as `page.tsx` and `layout.tsx`.
- Keep layouts and pages as Server Components by default. Add `'use client'` at the smallest boundary needing interaction, state, or browser APIs. Follow [Next.js component guidance](https://nextjs.org/docs/app/getting-started/server-and-client-components).
- Fetch application data from NestJS. Browser requests use `/api`; server rendering uses the configured API origin and forwards only required session context. Keep database access, OAuth, AI calls, and authorization in the API.
- Treat authenticated responses as private. Do not share cached user or channel data across sessions. Keep secrets out of browser bundles and `NEXT_PUBLIC_` variables.
- Keep state local unless multiple consumers need it. Derive values during rendering; use effects for synchronization with external systems. Add state or fetching libraries only for a demonstrated need.
- Use Tailwind consistently. Extract repeated UI patterns when they have a clear shared purpose; avoid building a speculative component system.
- Provide loading, empty, error, and submitting states. Show actionable failure messages and prevent duplicate submissions.
- Use semantic HTML, labeled inputs, keyboard-accessible controls, visible focus, and responsive layouts. Use links for navigation and buttons for actions.
- Render chat and AI content as text by default. Do not inject untrusted HTML. Hiding a control in the UI never substitutes for API permission checks.
- Ship features end to end with their backend behavior and contracts. A backend endpoint alone does not complete a user-facing feature.
- Test meaningful interactions and permission-dependent UI behavior as features are added. Verify mobile layout and keyboard navigation for changed screens.

Read the installed Next.js guides referenced by `apps/web/AGENTS.md` when using framework APIs.

Teams (`/app/team`, fixture: `?view=team`) lists every accessible channel with the current user’s role and switches the shared selected channel. Keep the directory visible to owners, moderators and team members. Only connected-channel owners load the private roster or see membership controls. Members can connect their own Twitch channel without leaving their other teams; joining another team still requires its owner to grant access.

Explain that Moderator grants Lore and Twitch moderation before the owner chooses it. Keep authorization inside the add/edit action: save a tab-scoped pending Moderator assignment, open Twitch consent when needed, and resume with a normal CSRF-protected grant after return. Bind the draft to the owner and channel, expire it after ten minutes, and consume it once; cancellation or missing permission must not grant access. Keep team-member grants usable. Show live Twitch verification separately from Lore access and offer explicit sync for legacy moderators. Never show success after failed promotion. Demoting a Moderator to Team member also removes Twitch moderation; removing a Moderator revokes both roles. Explain this in the removal confirmation. Resume the exact promotion, demotion or removal after Twitch consent; never convert a pending removal into a grant. Demo role changes remain simulated.

Candidate review lives at `/app/candidates` (fixture preview: `/demo?view=candidates`). Show original chat, cited words, evidence gaps, uncertainties, model and origin before offering a review. Confirmation requires an editable promise form and explicit action; dismissal requires a reason. Keep unavailable-source and disconnected states read-only. Provider consent is owner-only and explains sending retained chat to Gemini; missing configuration and failed runs have actionable states. Confirmed candidates link to their saved promise and brief. Preview review state persists in the workspace shell and never calls private APIs or a model.

Moderation cases live at `/app/moderation` and `/app/cases/[id]?channel=[channelId]`, with fixture equivalents in `/demo?view=moderation` and `?view=case&case=[id]&channel=[channelId]`. Only owners/moderators see case navigation; API access remains authoritative. Show rule snapshots, source origin/availability, retained proof, human history and read-only final decisions. Precedent panels distinguish retrieval similarity from evidence and show rule versions, comparisons, gaps, uncertainty, partial indexing and failure states. Preserve human edits while retrieval updates. AI drafts can fill a decision form only after an explicit click; require a human rationale and confirmation before saving. File uploads use the shared API client's multipart support and server limits; downloads navigate through the authenticated API. Preview files retain metadata only and cannot download or call R2.

The shift desk lives at `/app/moderation/workflows` (preview: `?view=workflows`). Case files include their consistency reviews and repair actions. Compare case rule versions, incidents, human rationale and retained-evidence availability before reviewing a concern; clearly label human flags versus deterministic outcome comparisons. Assignment lists include only current owners/moderators, and historical assignees who lost access are labeled unavailable. Require notes on task updates, reviews and action completion/cancellation; completed actions, resolved tasks and final reviews are read-only. Handoffs show their saved period, source links, outstanding tasks, recent decisions, documented rule changes and truncation warnings. New shifts begin pending even when a previous shift acknowledged the source. Keep preview workflow state in the persistent workspace provider and never call private APIs from previews.

Community publishing uses `/app/publications`, with fixture publishing/visitor views at `?view=publications` and `?view=community`. Draft preparation is available to active team members; owner/moderator approval requires a reason and a confirmation showing the exact public story and short chat wording. Editing a published entry returns it to draft; source changes withdraw dependent summaries. Keep private promise drafting references out of visitor projections. Chat authorization/readiness and opt-in are owner-only, separate from sign-in and capture consent. Preview never sends to Twitch.

Public `/c/[channel]`, `/catch-up` and `/entries/[id]` pages use the dedicated public API without session forwarding. Keep pages dynamic, use uncached requests and disable link prefetching for revocable stories. Revalidate on mount, tab visibility and every 30 seconds; clear displayed content on withdrawal or failed revalidation. Render plain text, approved public citations, publication dates, search/filter/pagination and useful empty/error states. Public pages use the same theme/type/surface tokens with a lighter community header and comfortable mobile reading width.

The stream overlay desk is `/app/overlay` (fixture: `?view=overlay`). Review the exact selected public display text before approval, keep private promises out of the selection list, and explain owner-only credential controls. Link generation returns a copy-once URL kept only in component memory; hiding/reloading discards it. Fixtures generate clearly invalid demo credentials and never call the display API. `/overlay/[channel]` renders a transparent canvas from first paint, reads the credential only from the fragment, requests display data without session cookies and stays blank on missing/invalid credentials or failed refresh. Keep request-order/expiry guards so delayed responses cannot restore a newer withdrawn display. Never show errors or workspace chrome on the stream canvas.

`/demo` loads the validated, uncached synthetic snapshot from `/api/demo` without forwarding session cookies. Inject its data into the existing fixture providers, retain state across demo navigation and remount every provider on reset. Build links through the workspace’s fixture base so case/detail/workflow links stay in `/demo`. A refresh loads the current seed; local changes must never persist to the server or trigger provider calls. Open the same Overview and task screens as the authenticated app, with simulated provider actions. Keep one compact Demo fixture bar and simulation labels; put the optional guide, command simulator, public preview and reset under Demo tools. If the API fails, times out or returns missing/invalid data, use the bundled `demoSeed` in the same playground. `/preview` permanently redirects to `/demo`, preserving query parameters; do not add a second preview entry point.

Pages render dynamically with a per-request CSP script nonce supplied by Next Proxy and passed to the theme provider. Keep scripts nonce-approved, fonts/assets local, and frames disabled; do not cache nonce-bearing HTML. Inline styles support current theme/avatar behavior. Browser journeys run against production builds to catch hydration/CSP, privacy, light/dark and mobile navigation failures. Mobile workspace navigation opens from a labeled Menu button, closes after navigation or Escape, and keeps links at comfortable tap sizes. Use the shared `Select` component for every app dropdown. Its Radix primitive handles focus, keyboard navigation, typeahead, dismissal and collision-aware popovers; keep Lore surfaces, disabled/required behavior and form values intact. The workspace header stays fixed; mobile navigation and channel controls reserve their combined height above content. Owner retention status uses current API counts and last completion, guards request ordering, and distinguishes loading, stale status, error/retry and successful cleanup; fixtures make no retention requests.

Workspace SSE lives in the shell and sends channel revisions only. Refresh data through existing scoped loaders; preserve forms after user input and show a reload notice instead of replacing edits. Always refresh consent and channel metadata, even while form refreshes are held. Candidate review includes opt-in microphone recording with local playback, explicit Gemini submission, track cleanup on close/navigation/visibility changes, and human confirmation. Public summary generation fills the existing editable draft form; it never invokes publication review itself.
